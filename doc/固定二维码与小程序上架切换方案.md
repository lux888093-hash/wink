# 固定二维码与小程序上架切换方案

- 更新日期：2026-05-13
- 适用范围：`a-quiet-world.com` 固定入口二维码、提取码页、小程序备案与正式上架

## 1. 本文结论

当前已经生成的固定二维码内容是：

```text
https://a-quiet-world.com/redeem
```

这个二维码是普通网址二维码，不是微信官方原生小程序码。

因此：

1. 用户扫码后看到 `a-quiet-world.com` 或直接进入网页，是正常现象。
2. 这个二维码可以长期固定不变，适合作为已经印刷或即将印刷的统一入口。
3. 后续可以通过修改 `https://a-quiet-world.com/redeem` 背后的页面逻辑，承接正式上线后的访问。
4. 但这个二维码后续不能无损变成“扫码后直接原生进入小程序”的微信官方小程序码。
5. 如果后续一定要实现“扫码即原生进入小程序提取码页”，需要重新生成并印刷正式小程序码。

一句话判断：

- 现有二维码适合做长期固定的外部入口。
- 正式小程序码适合做后续批次物料升级。

## 3. 为什么当前先用网址二维码

当前阶段不能把物料入口直接押在正式小程序码上，原因有三个：

1. 小程序未备案、未发布，正式线上入口尚未交付。
2. 正式 URL Link / URL Scheme / 正式小程序码都依赖线上已发布版本。
3. 客户已经着急出货，物料入口需要先固定。

因此，先把印刷入口固定为：

```text
https://a-quiet-world.com/redeem
```

是目前最稳妥的工程方案。

这个方案的优势是：

1. 先把印刷内容定住，不因为后续上线方式变化而重做版面。
2. 后续可在同一个地址后面切换占位页、H5 提取码页、H5 跳小程序页。
3. 已出货批次和未来批次都能共用同一外部入口。

## 4. 必须先说清的边界

### 4.1 现有二维码以后会一直被识别为“网址二维码”

这一点不会变化。

无论后面 `a-quiet-world.com/redeem` 页面做成什么样，扫码动作本身识别到的仍然是一个普通 URL，不会变成微信原生小程序码。

这意味着：

1. 扫码时，微信会先按网页入口处理。
2. 后续可以在网页里引导用户打开小程序。
3. 但体验上与“扫微信官方小程序码直接进页”不是一回事。

### 4.2 如果不重印，后续最现实的是“网址页承接，再打开小程序”

后续正式上架后，保留当前二维码不变时，推荐用户链路是：

```text
扫码固定二维码
-> 打开 https://a-quiet-world.com/redeem
-> 网页展示“打开小程序”按钮
-> 拉起正式小程序
-> 进入 pages/redeem/index
```

这条路可以做，而且适合已经印出去的物料。

但它不是：

```text
扫码
-> 直接原生进入小程序
```

### 4.3 如果你要最干净的扫码体验，后面需要二次印刷正式小程序码

后续正式发布后，最好的用户体验仍然是：

```text
扫码正式小程序码
-> 直接进入 pages/redeem/index
```

也就是说，当前固定网址二维码解决的是“先出货”和“入口不返工”，不是“最终原生扫码体验最优”。

## 5. 当前阶段该怎么用这个二维码

### 5.1 如果客户现在就要能扫、能用

建议把 `https://a-quiet-world.com/redeem` 先部署到中国大陆以外节点，例如香港或海外静态托管/CDN 节点，用来承接一个临时网页。

临时网页有两个可选模式：

1. 占位页模式  
   适合先出货、稍后再开放使用。页面只说明提取码入口即将开通，请保留提取码和包装。

2. 临时 H5 提取码页模式  
   适合客户收到货后立刻需要使用。页面先做一版网页提取码输入，后续再切换为小程序承接页。

注意：

1. 如果域名未完成中国大陆 ICP 备案，就不要把这个 H5 放在中国大陆服务器上。
2. 如果只是临时网页承接，先放海外/香港节点更稳。

### 5.2 如果客户现在只要求先把物料印出来

可以只固定二维码内容，不急着开放页面功能。

这种情况下：

1. 包装上印当前二维码。
2. 先把页面做成简单占位页。
3. 待小程序备案并发布后，再切换该地址的页面逻辑。

## 6. 后续正式上架的两条路线

### 6.1 路线 A：不重印，保留当前二维码

这是最适合当前批次出货的路线。

上线后的实现方式：

1. 保留印刷二维码不变：`https://a-quiet-world.com/redeem`
2. 该地址打开一个正式 H5 承接页
3. 在微信内展示“打开小程序”按钮或跳转方案
4. 用户再进入正式小程序提取码页

优点：

1. 不需要重印已经出货或已下单的包装。
2. 入口统一，后续运营和客服口径简单。
3. 可以兼容微信内外不同访问环境。

缺点：

1. 不是原生小程序码体验。
2. 扫码后通常会先进入网页承接层。
3. 部分浏览器或环境下，网页直接拉起小程序存在交互限制，通常需要按钮确认。

适用场景：

1. 当前批次必须尽快出货。
2. 包装已经准备印刷或已经印出。
3. 允许接受“先网页、再小程序”的用户路径。

### 6.2 路线 B：后续新增正式小程序码物料

这是体验最好的路线，适合后续新批次物料。

上线后的实现方式：

1. 小程序完成备案、审核、发布。
2. 调用项目里的正式固定小程序码接口。
3. 生成指向 `pages/redeem/index` 的正式固定小程序码。
4. 新批次包装、卡片、宣传物料改印正式小程序码。

优点：

1. 扫码直接进入小程序提取码页。
2. 用户路径最短。
3. 更符合“固定小程序码 + 六位提取码”原始产品设计。

缺点：

1. 需要更新物料。
2. 已出货批次仍需继续兼容旧二维码。

适用场景：

1. 第二批、第三批或后续正式版包装。
2. 对扫码体验要求更高。
3. 接受更新印刷物料。

## 7. 推荐的最终策略

本项目最建议采用“双轨并行”：

1. 旧物料、当前急出货批次：继续使用当前固定网址二维码。
2. 新物料、后续正式批次：升级为正式小程序码。

这样处理的结果是：

1. 当前不会因为等待备案而卡住出货。
2. 已经印出去的二维码不会废掉。
3. 正式上线后，新物料可以切到更好的原生扫码体验。

## 8. 正式上架前的执行清单

以下按实际落地顺序执行。

### 8.1 先完成小程序备案

按照微信官方备案流程，准备并提交：

1. 主办单位证件
2. 主体负责人证件
3. 小程序负责人证件
4. 如有需要的前置审批/专项审批材料
5. 平台内完成负责人核验照片与承诺书确认

官方备案流程为五个环节：

1. 备案信息填写
2. 平台初审
3. 工信部短信核验
4. 通管局审核
5. 备案成功

对于未上架小程序，官方备案入口已经开放，可在小程序后台直接进入备案流程。

### 8.2 明确域名用途并拆分

建议后续至少拆成以下用途：

1. `a-quiet-world.com`  
   对外品牌主域名，可保留给宣传页或统一跳转入口。

2. `a-quiet-world.com/redeem`  
   当前已经印刷固定二维码对应的永久入口，不建议后续改路径。

3. `api.a-quiet-world.com`  
   小程序正式接口域名，专门给 `wx.request` 使用。

4. `h5.a-quiet-world.com` 或直接主域名下页面  
   如后续需要 `web-view` 或网页承接，可单独规划。

这样做的好处是：

1. API、H5、主站职责分离。
2. 后续证书、缓存、CORS、风控更容易管理。
3. 不会把根域名入口和 API 耦合在一起。

### 8.3 确认中国大陆 ICP 备案范围

如果后续以下能力部署在中国大陆服务器上，需要完成对应域名的 ICP 备案：

1. 小程序正式请求接口域名
2. 小程序下载域名
3. 小程序 `web-view` 业务域名
4. 面向用户访问的正式 H5 页面

项目后续如果在小程序里使用网络请求，微信官方要求：

1. 域名必须是 HTTPS
2. 不能使用 IP 或 localhost
3. 域名必须经过 ICP 备案

如果后续在小程序里使用 `web-view` 承载网页，微信官方要求：

1. 业务域名必须为 HTTPS
2. 业务域名需经过 ICP 备案
3. 新备案域名需 24 小时后才可配置

### 8.4 部署正式服务并补齐环境变量

参考现有运维手册，生产环境至少补齐：

1. `APP_ENV=production`
2. `MINIPROGRAM_BASE_URL=https://你的正式域名`
3. `CORS_ALLOWED_ORIGINS=https://你的正式域名`
4. `DATABASE_URL` 或 `PGHOST/PGDATABASE/PGUSER/PGPASSWORD`
5. `ADMIN_SESSION_PEPPER`
6. `ADMIN_BOOTSTRAP_PASSWORD`
7. `MINIAPP_SESSION_SECRET`
8. `WECHAT_APPID`
9. `WECHAT_APPSECRET`
10. 微信支付相关变量

这部分可直接对照：[doc/上线验收与运维手册.md](</D:/AI/hongjiu/doc/上线验收与运维手册.md:6>)

### 8.5 配置微信后台域名

小程序正式联调时，需要在微信后台配置：

1. request 合法域名
2. upload 合法域名
3. download 合法域名
4. socket 合法域名（如有）
5. 业务域名（如使用 `web-view`）

注意：

1. `api.weixin.qq.com` 不能作为小程序服务器域名配置到前端。
2. AppSecret 必须放在你自己的后端服务器中，由后端去调用微信接口。

### 8.6 上传代码、提审、发布

正式上线按微信官方标准流程走：

1. 预览
2. 上传代码
3. 提交审核
4. 发布

版本管理上要区分：

1. 开发版本
2. 体验版本
3. 审核中版本
4. 线上版本

建议在正式提审前，先完成真机验收，再提审，不要用高频试错的方式消耗审核机会。

### 8.7 发布后生成正式固定小程序码

等小程序已经存在线上版本后，可使用项目现有接口生成正式固定小程序码。

项目当前配置目标页为：

```text
pages/redeem/index
```

服务端固定码接口：

```text
POST /api/admin/qrcode/fixed-redeem
```

当前服务端生成逻辑使用的是微信官方 `getUnlimitedQRCode` 能力，会写出固定二维码文件。

这一步适合做两件事：

1. 生成正式交付版小程序码图片留档
2. 给后续新批次包装替换为正式小程序码

## 9. 关于“现有二维码后续能不能直接跳小程序”的准确说法

准确说法如下：

1. 可以复用当前二维码，不必作废。
2. 复用后可以把它做成“小程序承接入口”。
3. 但它本质上仍然是网址二维码，不是微信原生小程序码。
4. 不重印的前提下，后续通常是“网址页承接，再打开小程序”。
5. 如果一定要求“扫码直接原生进小程序提取码页”，仍需正式小程序码。

这段话建议后续对客户、设计、包装供应商统一口径，避免误解。
